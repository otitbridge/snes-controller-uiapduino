# 最小HIDファームウェアの試験準備と書き込み結果

P2でビルドしたUIAPduino単体の試作品です。2026-11-10に全キー解放版と手動単キー版の書き込み・読み戻し検証を行い、MacでUSB認識と、手動単キー版の押下・保持・解放を確認しました。この手動単キー版ではiPhone／Deltaを試験していません。その後の統合版では、iPhoneのGBAゲームでB操作3回の成功が本人から報告されました（[P4の結果](validation.md#p4のiphonedelta初期試験gba)）。

その後、基板はSFC診断版を経て [SFCキーボード統合版](sfc-keyboard.md) へ書き換えています。このページの単キー試験を再開するときは、SFCのCLOCK配線を外して `manual` へ戻します。

## 全キー解放版の書き込み結果

`32V003`（VID:PID `1209:B803`、`bcdDevice=0x0141`）を1台検出し、本人が接続したV1.4の書き込み対象と対応づけました。`uiapflash` 1.0.0で3116バイトのBINを3136バイトへパディングして書き込み、全セクタの読み戻し一致とアプリ起動に成功しました。

起動後は同じUSB接続位置で `UIAPduino KBD+Mouse`（`1209:D004`）が列挙され、Usage Page 1／Usage 6・入力レポート8バイトのキーボードと、Usage 2のマウスをmacOSのIORegistryで確認しました。証拠は [書き込み記録](evidence/p2-upload-neutral-2026-11-10.json) に保存しています。

## 手動単キー版の書き込み結果

本人がジャンパ線を開放した状態で再接続しました。最初は実行中の `1209:D004` のままで、書き込みは開始していません。RESETを押してUSBを接続し、接続直後に離す手順で `32V003`（`1209:B803`、記述子 `0x0141`）を1台検出しました。このタイミングは [メーカーの手順](https://www.uiap.jp/uiapduino/pro-micro/ch32v003/v1dot4) に従っています。

既存の `manual` BIN（4084バイト、SHA-256 `254251c3e42635c5795f7e42b8e94872541dd205eb29f0f32330f4e182a7c00d`）を4096バイトにパディングして書き込みました。`uiapflash` 1.0.0は2周目に全セクタ一致、ベリファイOK、アプリ起動、終了コード0となり、同じUSB接続位置で `1209:D004` が再認識されました。途中の0バイト受信診断25件も [記録](evidence/p2-manual-hid-2026-11-10.json) に残しています。ブートローダ領域の書き換えは行っていません。

## Macでの単キー試験結果

初回に反応しなかった際、本人から、基板の「5」とGNDを接続していたとの訂正がありました。「7」（PC5）とGNDへ変更した後は、同じファームウェアのまま正常に反応しました。ピンヘッダははんだ付け済みとの本人申告です。

macOS 26.7.1／Safari 27.0の [入力確認画面](../tests/keyboard_probe.html) で、ジャンパ線だけによる3回の押下・保持・解放を実施しました。保持時間は6.084秒、6.121秒、30.908秒で、いずれも開放後のZキー解放を画面と本人の報告で確認しました。画面には、それらに先行する短い0.060秒・0.007秒の2回も記録されています。短い入力の原因やデバウンス性能は測定していません。

これはブラウザのキーイベントによる確認で、Raw HID取得やSFC入力の試験ではありません。試験条件と限界は [validation.md](validation.md) と [JSON記録](evidence/p2-manual-hid-2026-11-10.json) に保存しています。この手動単キー版のiPhone／Deltaは未確認で、後の統合版によるGBA試験と区別します。

## 2つのモード

| ビルド | 入力 | 生成する状態 |
| --- | --- | --- |
| `neutral`（既定） | GPIOを使用しない | 常に全キー解放 |
| `manual` | PC5／`GPIO_PIN_7`、`INPUT_PULLUP` | LOWの間だけB→Z（Raw Usage `0x1D`）、HIGHで全解放 |

どちらもUSBモードはKeyboard+Mouseで、マウスの操作はしません。自動でキーを押す動作はありません。`manual` は外部の手動スイッチを使う試験専用です。

## 構成と契約

- `snes_controller.ino`：開始処理と約10msの更新周期。SFC読み取りは含まない。
- `board_config.h`：既定は `SNES_HID_TEST_INPUT=0`。試験スイッチはビルド時に明示的に有効化する。
- `usb_backend.cpp`：`SnesHid::makeReport()` の結果を `uiapkbd_keyboard_set()` へ渡す。ASCII変換・Report IDの追加・`Keyboard.write()` は使用しない。

`UsbBackend::begin()` は全解放を設定してから `uiapusb_begin()` を呼びます。以降は現在の状態全体を設定し、保持中に余計な全解放を挟みません。バッファ設定は送信完了ではないため、開始時の全解放をホストが受信したことまでは保証しません。

## 共有バッファと今回の範囲

コア1.2.15は8バイトの共有状態を1バイトずつ更新し、USB割り込み側が読みます。このページの2モードはパッチを当てず、その実装を使います。`neutral` は変化せず、`manual` も変化するのは単キーの1バイトだけです。後のSFCキーボード統合版だけは [専用パッチ](../patches/README.md) で完成した状態を公開します。

ホストの取得前に押下・解放を上書きする短押しの欠落、サスペンド・再接続時の同期は未確認です。無制限のイベントキューや推測による転送完了状態は追加していません。手動スイッチは10msごとに読むだけで、デバウンスや最小押下時間の保証もありません。

## 再試験と残りの手順

以下の1～4は実施済み、5はこの手動単キー版では未実施です。iPhone試験は統合版と実物のSFCボタンで進めています。現在の基板はGET_REPORT(Input)応答を含む通常版 `sfc-keyboard` へ切り替え済みで、書き込み・読み戻し・Mac列挙を確認しました。先行するiPhone／DeltaのD10は計測版初版（trace v1）の結果で、通常版の操作確認も今回の合意範囲で完了しました。現在の合否は [検証一覧](validation.md) を参照してください。手動単キー版へ戻す必要はありません。書き込みモードへの移行は、基板のRESETボタンを押したままUSBを接続し、接続直後に離します。通常の動作試験ではRESETを押さずに接続します。再書き込み時も対象デバイスを照合します。

1. `neutral` をビルドし、識別した実物へ書き込む。Macでのキーボード列挙は確認済み。キー入力の観察は別途記録する。
2. 給電を外し、実物のPC5の接続点を確認する。PC5は基板に「7」と表示された端子で、「5」の端子ではない。左右両列にある「7」は同じPC5へ接続されている（[メーカーの配置図](https://www.uiap.jp/img/UIAPduino-Pro-Micro-CH32V003-V1dot4-Pinout-Diagram-s.avif)）。「7」とGNDの間をジャンパ線で接続・開放する。書き込み時は開放する。Arduino番号7を、ICの物理ピン番号7とは扱わない。SFC基板は接続しない。
3. `manual` をビルドして対象へ書き込む。PCのブラウザで [単キー入力確認画面](../tests/keyboard_probe.html) を開き、「記録を消して開始」をクリックしてからジャンパ線を操作する。
4. 5秒の接続・開放を2回、30秒以上の接続・開放を1回行う。接続中は「Z：押下中」、開放後は「Z：解放」になることを確認する。試験中は画面を表示したまま、PC側のZキーを押さない。回数・保持時間・フォーカス喪失・ケーブル・ホストOS・観察結果を記録する。
5. PCで確認できた後、iPhone 17へ接続する。Deltaの設定 → ControllersのPlayer 1 → キーボード → Customize Controlsで対象システムを選び、BへのZ割り当てと実際の操作を確認する。手順の参照元は [Delta公式ガイド](https://faq.deltaemulator.com/using-delta/controllers)。iPadは端末別に追加する。

MacでのRaw HID取得は、専有時に `kIOReturnNotPrivileged`、非専有時に `kIOReturnExclusiveAccess` で失敗しました。代わりの確認画面はブラウザが受け取った `KeyboardEvent` を記録します。USBレポートや入力元デバイスの識別情報は取得しません。Z入力の出所は、本人がジャンパ線だけを操作する手順と対応づけます。

ビルドコマンドとサイズは [build.md](build.md)、実施状況は [validation.md](validation.md) を参照してください。
