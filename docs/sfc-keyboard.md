# SFCキーボードの仕様と入力確認

`sfc-keyboard` はSFCコントローラーの12ボタンをUSB HIDキーボードへ変換する通常版です。CLOCK＝UIAPduinoの7、LATCH＝8、DATA＝9、電源＝5VとGNDを使用します。接続は [配線表](wiring.md#接続表)、導入は [ビルド・書き込み手順](getting-started.md) を参照してください。

## 入力とUSB出力

約10msごとにSFCの16ビットを読み取り、LOWを押下として下位12ビットを使用します。読み取り順はB、Y、SELECT、START、上、下、左、右、A、X、L、Rです。キー割り当ては [README](../README.md#キー割り当て) に記載しています。SELECTはTabです。

レポートは修飾キー1バイト、予約1バイト、キー6枠の計8バイトです。修飾キーは使用しません。USBではKeyboard+Mouseとして列挙されますが、マウス操作は出力しません。

## 同時押しと部分解放

最大6キーを出力します。7入力以上の場合は、次の順序で先頭6個を選びます。

```text
B → Y → SELECT → START → 上 → 下 → 左 → 右 → A → X → L → R
```

これは本ファームの選択規則です。6キー以内へ戻ると、その時点で保持している入力から出力を再計算します。

例えばB＋Y＋SELECT＋START＋L＋Rを保持して上を加えると、Rに対応するWが出力枠から外れます。上だけを離すとWが戻ります。右＋Y＋BからBだけを離す場合は、右＋Yを維持します。

## 通常版のビルド設定

```sh
bash scripts/build_firmware.sh sfc-keyboard
```

| 設定 | 値 |
| --- | --- |
| コア | `UIAP_HID:ch32v@1.2.15` の専用コピー |
| USB | `usb=kbd` |
| 入力モード | `SNES_SFC_KEYBOARD=1`、単キー・診断モードは0 |
| CLI設定 | `.local/sfc-arduino-cli.yaml` |
| 生成先 | `.local/build/sfc-keyboard/` |
| 確認済みBIN / 静的RAM | 5,496 / 196バイト |

専用コピーには [共有状態とGET_REPORT応答のパッチ](../patches/README.md) を適用します。元の導入済みコアは保持します。未変更コアでの通常版や、複数の入力モードの同時指定はコンパイルで拒否します。FQBN・取得物の検証は [ビルド詳細](build.md) を参照してください。

## Macでのキー操作確認

通常版を書き込んだ基板を、全ボタンを離してMacへ通常接続します。RESETは押しません。新しいログ名で記録画面を起動します。

```sh
python3 scripts/serve_keyboard_probe.py sfc-keyboard-trial.jsonl
```

表示された `http://127.0.0.1:ポート番号` をSafariで開き、「記録を消して開始」をクリックします。SFCだけを操作し、パソコンのキーは押さず、画面を前面に保ちます。

1. 全12ボタンを1個ずつ押し、正しいキーが反応して解放へ戻ることを確認します。
2. 左右を各30秒以上保持し、途中で切れず、離すと止まることを確認します。
3. 右＋Y＋Bを保持し、Bだけを離して右＋Yが残り、その後全解放することを確認します。
4. B＋Y＋SELECT＋START＋L＋Rの6入力を保持し、上を追加します。Wが外れ、上だけを離すとWが復帰することを確認します。

ログは `.local/logs/` に保存します。既存ログは上書きできないため再試験では別名を使い、終了時はCtrl+Cでサーバーを止めます。保持中にフォーカスが外れた区間は判定から除外してください。

記録はブラウザのキーイベントで、USBパケットや入力元デバイスの識別情報ではありません。実施済みの結果は [検証結果](validation.md) にまとめています。

## USB側の状態管理

起動前に全解放を設定し、読み取った最新状態をコアへ渡します。共有状態のパッチは完成した8バイトの状態を公開することで、更新途中の内容が送信側に混在することを防ぎます。GET_REPORT(Input)要求にはキーボード8バイト、マウス4バイトの状態を返します。

`UsbBackend::stageButtons()` は戻り値のない関数です。状態の更新はホストへの到達・転送完了・ゲームへの反映を意味しません。短押しの保存や接続・スリープ復帰時の同期を保証するものでもありません。SFC読み取りと状態の公開中にUSB割り込みは禁止しません。

接続時保持・ロック復帰の未解決事項と、使用時の対処は [既知の問題](known-issues.md) を参照してください。実装の導入・試行履歴は [開発記録](development/sfc-keyboard-history.md) に保存しています。
