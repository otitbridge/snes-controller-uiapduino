# SFC入力からUSBキーボード出力への統合

実配線後の全12入力・長押し・部分解放の診断を終え、`sfc-keyboard` モードを追加しました。
確認済みのCLOCK＝UIAP 7、LATCH＝8、DATA＝9と、5V電源／GNDの配線を使用します。
[配線表](wiring.md) を参照してください。配線変更はUSBを外して行います。

## ビルド

```sh
bash scripts/build_firmware.sh sfc-keyboard
```

コアは `UIAP_HID:ch32v@1.2.15` を元に、[共有状態のパッチ](../patches/README.md) を専用コピーへ
適用します。既存の導入済みコアは保持します。USBは `usb=kbd`（Keyboard+Mouse）で、マウスは操作しません。
BINは5,360バイト、静的RAMは188バイトです。CLIのFlash表示5,200バイトに `.init` 160バイトを加えた値がBINと一致します。

生成先は `.local/build/sfc-keyboard/`、使用するCLI設定は `.local/sfc-arduino-cli.yaml` です。
SFCキーボード用フラグは `SNES_SFC_KEYBOARD=1`、他の入力モードは0です。
未変更コアでのこのモード、診断との同時指定、単キー試験との同時指定はコンパイルで拒否します。

起動前に全解放を設定し、約10msごとに現在のSFC状態を読み、[引き継ぎ仕様のキー表](../SNES_UIAPduino_CODEX_HANDOFF.md#6-入力仕様キー割り当て)
へ変換します。下位bit順の先頭6キーだけを採用し、7キーから6キーへ戻ると保持中のキーを再計算します。
SFC読取中も、キーボード状態の公開中も、USB割り込みを禁止しません。

## 検査済みの範囲

- 実際のスケッチ・SFC読取・USBバックエンドをホスト上で接続し、全4,096通りの入力、保持、部分解放、6キー上限からの復帰を確認。
- 実際のコアのsetterとUSB読取を使った割り込みモデルで、元コアの混在を再現し、変更後は147,456回の挿入点で完全な旧状態または新状態だけを確認。clearと反復保持も対象。
- 上記を通常構成とAddressSanitizer／UndefinedBehaviorSanitizerの両方で確認。
- RISC-Vの生成コードで8バイトの書込後に1バイトの公開索引をstoreし、USB側は索引を1回loadして送信することを確認。
- 従来の `neutral`、`manual`、`sfc-diagnostic` は、実機確認済みのBINとハッシュが一致。

これらはビルド・ホスト検査です。統合版の書き込みとMacでのキー操作は次節に分けて記録します。
最新の実施状態は [検証結果](validation.md) と [統合版の記録](evidence/p3-sfc-keyboard-2026-11-10.json) を参照してください。

## 書き込みとMac試験の結果

2026-11-10、`32V003`／`1209:B803`／記述子 `0x0141` の1台とBIN・ツールのハッシュを照合して書き込みました。
初回は `0x08000540` でFeature Reportの受信に失敗しました。後から本人より、書き込み中にUSBを抜き差ししたためとの申告があり、通信失敗のログと分けて記録しました。
同じ対象とBINで再試行し、5,376バイトの全セクタ読み戻し一致とアプリ起動に成功しました。ブートローダ領域は書き換えていません。

現在の基板はこの `sfc-keyboard` で、MacにはKeyboard+Mouseとして認識されています。
Safari 27.0の試験画面で、本人がSFCだけを操作し、次を確認しました。

| 操作 | 観測した結果 |
| --- | --- |
| 全12ボタンを単独操作 | 指定された12キーの押下・解放が順に届き、各回全解放 |
| 左右の保持・解放 | 左43.089秒、右36.649秒。保持中断・他キー混入なし |
| 右＋Y＋BからBだけ解放 | 3キーを7.576秒保持した後、右＋Yが6.188秒残り、最後は全解放 |
| B＋Y＋SELECT＋START＋L＋Rに上方向を追加・解放 | 7入力時にR→Wが外れ、上を離すとR→Wが復帰。5回確認し、最後は全解放 |

最初の2回の上限試験では、所定の6入力を維持できた記録が揃わず、7入力からの復帰判定には使っていません。
上表の最後の組み合わせへ変更した再試験で確認しました。手操作とデバイス動作のどちらが最初の崩れの原因かは独立に測定していません。
合格に使った操作区間にフォーカス喪失はありません。これらはブラウザのイベントで、Raw HIDレポートではありません。

## Macでのキー操作確認

書き込みは [build.md](build.md#usb契約と確認済みの書き込み方法) の対象確認を行い、
`.local/build/sfc-keyboard/snes_controller.ino.bin` を使用します。USBを抜き、RESETを押しながらMacへ接続し、
接続直後にRESETを離して書き込みモードへ入ります。SFCの全ボタンを離して操作します。

Mac内だけで動く記録画面を起動します。ログ名は毎回新しい名前にします。

```sh
python3 scripts/serve_keyboard_probe.py sfc-keyboard-trial.jsonl
```

表示された `http://127.0.0.1:ポート番号` をSafariで開き、「記録を消して開始」をクリックします。
SFCだけを操作し、パソコンのキーは押さず、画面を前面に保ちます。フォーカスが外れた区間の保持は合格に含めません。
サーバーはこのページの12キーとフォーカス状態だけを `.local/logs/` へ保存します。
記録はブラウザのキーイベントで、USBレポートのバイト列や入力元デバイスの識別ではありません。
SFCを操作したことは本人の手順・申告と対応づけます。

1. 全12ボタンを1個ずつ押し、各キーが解放へ戻ることを確認。
2. 左右を各30秒以上保持し、途中で切れず、離すと止まることを確認。
3. 右＋Y＋Bを保持し、Bだけを離して右＋Yが残り、その後全解放することを確認。
4. B＋Y＋SELECT＋START＋L＋Rの6入力を保持し、上方向を追加する。7入力時はR→Wが外れ、上を離すとWが復帰することを確認。

## 残る制限

パッチは完全な最新状態を公開するだけです。setterはvoidのままで、ホスト受信、転送完了、
ゲームでの反映を保証する戻り値はありません。短押しの保持、再接続・スリープ通知、
起動時のニュートラル到達も保証しません。これらとiPhone／Deltaでの動作は個別に実機確認します。
vendor HIDのSFC診断版と、キーボード出力のこのモードは別ビルドです。
