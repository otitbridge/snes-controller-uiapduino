# キー変換の検証と最小HIDのビルド結果

2026-11-10（日本時間）、P1のホスト上の純粋ロジックテストでL01～L03がPASS、P2では最小HIDのビルド・ホストテストと、全キー解放版の実物への書き込み・MacでのUSB列挙に成功しました。実キーの押下・保持・解放は未実施です。

## P1の条件と証拠

- 実施：Codexがローカルのコマンド実行結果を確認。
- 対象：`firmware/snes_controller/snes_hid_report.h` の12ビット入力から8バイトのHIDレポートへの変換。
- ベースコミット：`112a816`。P1の変更は実行時点で未コミットのため、[実行記録](evidence/p1-host-tests-2026-11-10.json) のソースSHA-256で特定。
- OS／CPU：macOS 26.7.1／Darwin arm64。
- コンパイラ：Apple clang 21.0.0（`c++`）、C++14。`-Wall -Wextra -Werror -pedantic -DNDEBUG` を指定。
- 実行方法：通常の `-O2` と、`-O1`＋AddressSanitizer／UndefinedBehaviorSanitizerの2構成。両方とも終了コード0、警告・sanitizer診断なし。
- バイナリ：`.local/host-tests/hid_report_test` と `hid_report_test_sanitized`。ホスト用実行ファイルであり、MCU用ファームウェアではない。SHA-256は実行記録に保存。
- MCU用のコア／FQBN／USBモード／Flash・RAM使用量：今回のホストテストでは対象外。
- 実物の基板・コントローラー・接続ピン・端末・Delta・ケーブル：今回の試験では使用していない。

再実行コマンド（プロジェクトのルート）：

```sh
bash tests/run_host_tests.sh
SNES_HOST_SANITIZERS=1 bash tests/run_host_tests.sh
```

## 実施したロジック試験

| ID | 条件・手順 | 期待結果 | 実際の結果 |
| --- | --- | --- | --- |
| L01 | 全解放、全12ボタンを各1入力、全ボタン入力を与える。ボタンのビット定義も確認 | 引き継ぎ仕様のUsage ID。modifiers／reservedは0、未使用枠は0 | PASS、通常・sanitizerの両構成 |
| L02 | 下位12ビットの全4096通りを列挙。キーの所属・順序・個数・重複・0埋めを確認 | 押下ボタンのうちbit順の先頭6個だけが出力される | PASS、全4096通り |
| L03 | 7キー→6キーの具体例と、全4096通りの押下状態から1ボタンずつ離す24576通りを確認 | 解放したキーが消え、枠が空けば除外されていた保持キーが現れる | PASS、具体例と全24576通り |

L03の具体例は、右＋B＋Y＋A＋L＋RへSTARTを加えるケースです。7キー時はRが出力枠から外れ、STARTを離すとRが復帰しました。これはレポートのバイト列に対する確認で、DeltaのD05試験は未実施です。

追加で以下を確認しました。

- 全65536通りの `uint16_t` 入力で、上位4ビットを変えても出力が変わらない。
- 単キー・3キー・12キーの入力をそれぞれ3000回与えてもレポートが変わらない。
- 全4096通りで、途中に別の押下状態を挟んでも元の入力に対する結果が変わらない。
- 右＋Y＋BからBだけを離したとき、右とYが残る。全解放で全キー枠が0になる。
- 8バイトのサイズ、各フィールドの位置、コピー可能な構造を確認。
- `Keyboard` というグローバルオブジェクトをテスト側で定義してもコンパイルできる。実際のArduino `Keyboard.h` との統合ビルドはP2で扱う。

3000回の反復は状態の不変性を確認するための呼び出し回数です。実時間の30秒保持、USBでの保持、短押しの最小時間を測ったものではありません。

- 実施：CodexがローカルのCLI・コンパイラ・テストの結果を確認。
- ベースコミット：`3b961e0`。P2の変更は実行時点で未コミット。ソース・成果物は [P2の記録](evidence/p2-build-2026-11-10.json) のSHA-256で特定。
- 環境：macOS 26.7.1／Apple Silicon、Arduino CLI 1.5.1 x86_64、xPack RISC-V GCC 14.2.0-2。
- コア：`UIAP_HID:ch32v@1.2.15`、参照SHA `9471a150c9837c9055ef62ef759a1a593eddf1b1`、パッチなし。配布物全730ファイルを導入内容と照合済み。
- FQBN・USB：V1.4、48MHz HSI、`usb=kbd`、UARTなし、`-Os -flto`。完全なFQBNとコマンドは [build.md](build.md) とJSON記録に保存。
- 基板：本人申告のV1.4・5Vを対象にした設定。この節のビルド時点では書き込み・実測は行わず、その後の書き込み結果は次節へ記録。

| ビルド | 条件 | BIN | CLIのFlash表示 | 静的RAM | 状態 |
| --- | --- | ---: | ---: | ---: | --- |
| `neutral` | GPIOを読まず全解放 | 3116バイト | 2956バイト | 156バイト | ビルド成功（書き込み結果は次節） |
| `manual` | PC5のLOWでB→Z | 4084バイト | 3924バイト | 176バイト | ビルドのみ（終了コード0） |

CLIのFlash集計には `.init` が含まれず、今回の差は両ビルドとも160バイトです。容量はボード定義上Flash 16,384／RAM 2,048バイトで、リンカはスタック用境界として448バイトを置きます。実際のスタック余裕やブートローダとのメモリ整合は未測定・未確認です。

バックエンドは、開始前の全解放、Zキー保持・解放、部分解放、6キー上限からの復帰、Raw Usage IDと8バイト状態の受け渡しをテストダブルで確認しました。P1テストと合わせ、通常・sanitizerの両構成でPASSです。キーボード用モード未指定とWebHID-onlyとの競合も、コンパイルで拒否されました。

これらのテストはvoid setterへの引数と呼び出し順を対象にしており、USB割り込み・ホスト受信・再接続の証拠ではありません。共有バッファは逐次更新のまま、最小ファームの実機用入力は全解放と単キーだけに限定しています。

## 全キー解放版の書き込みとU01

- 日時：2026-11-10、日本時間。正確な開始・終了時刻は [書き込み記録](evidence/p2-upload-neutral-2026-11-10.json) に保存。
- 実施：本人が基板を接続・書き込みモードへ再接続し、Codexがデバイス情報・書き込みログ・USB／HID情報を確認。
- ファーム：`neutral`、3116バイト、SHA-256 `27f8d5e11dca454433b8b6eccff781035236165d22fe5e462c79b2b9841233bd`。ソースはP2ビルド記録のSHA-256で特定。
- 書き込み前：`32V003`、VID:PID `1209:B803`、`bcdDevice=0x0141` の対象が1台。本人申告の基板V1.4・5V、実測電圧は未記録。
- 使用ツール：`uiapflash` 1.0.0、macOS用。配布物と実行バイナリの一致も確認。
- 書き込み：`0x08000000`～`0x08000C3F`、3136バイトにパディング。2周目に全セクタ一致、ベリファイOK、アプリ起動、終了コード0。
- 診断：途中に0バイトの受信診断があり、その後に読み戻し一致まで完了。詳細はstderrも含めて記録。
- 書き込み後：同じUSB接続位置に `UIAPduino KBD+Mouse`（`1209:D004`）が列挙。macOSのIORegistryにキーボード（Usage Page 1／Usage 6、入力8バイト）とマウス（Usage 2、入力4バイト）が現れた。
- 判定：書き込み・読み戻し検証はPASS。U01のPCでのUSBキーボード認識もPASS。
- 未確認：実キー入力、USB-Cの反転・再接続反復、スリープ復帰、SFC読み取り、iPhone／Delta、iPad。ケーブルの型番・実測電源・ブートローダ全体のハッシュは未記録。

ブートローダ領域の書き換えは実施していません。今回の成功を手動スイッチ版やSFC入力の実機合格へ一般化しません。
