# キー変換の検証結果

2026-11-10（日本時間）、P1のホスト上の純粋ロジックテストを実施し、L01～L03がPASSでした。USBや実物のボタンからの入力は対象にしていません。

## 共通の条件と証拠

- 実施：Codexがローカルのコマンド実行結果を確認。
- 対象：`firmware/snes_controller/snes_hid_report.h` の12ビット入力から8バイトのHIDレポートへの変換。
- ベースコミット：`112a816`。P1の変更は実行時点で未コミットのため、[実行記録](evidence/p1-host-tests-2026-11-10.json) のソースSHA-256で特定。
- OS／CPU：macOS 26.7.1／Darwin arm64。
- コンパイラ：Apple clang 21.0.0（`c++`）、C++14。`-Wall -Wextra -Werror -pedantic -DNDEBUG` を指定。
- 実行方法：通常の `-O2` と、`-O1`＋AddressSanitizer／UndefinedBehaviorSanitizerの2構成。両方とも終了コード0、警告・sanitizer診断なし。
- バイナリ：`.local/host-tests/hid_report_test` と `hid_report_test_sanitized`。ホスト用実行ファイルであり、MCU用ファームウェアではない。SHA-256は実行記録に保存。
- MCU用のコア／FQBN／USBモード／Flash・RAM使用量：今回のホストテストでは対象外。
- 実物の基板・コントローラー・接続ピン・端末・Delta・ケーブル：今回の試験では使用していない。

再実行コマンド（プロジェクトのルート）：

```sh

SNES_HOST_SANITIZERS=1 bash tests/run_host_tests.sh
```

## 実施したロジック試験

| ID | 条件・手順 | 期待結果 | 実際の結果 |
| --- | --- | --- | --- |
| L01 | 全解放、全12ボタンを各1入力、全ボタン入力を与える。ボタンのビット定義も確認 | 引き継ぎ仕様のUsage ID。modifiers／reservedは0、未使用枠は0 | PASS、通常・sanitizerの両構成 |
| L02 | 下位12ビットの全4096通りを列挙。キーの所属・順序・個数・重複・0埋めを確認 | 押下ボタンのうちbit順の先頭6個だけが出力される | PASS、全4096通り |
| L03 | 7キー→6キーの具体例と、全4096通りの押下状態から1ボタンずつ離す24576通りを確認 | 解放したキーが消え、枠が空けば除外されていた保持キーが現れる | PASS、具体例と全24576通り |

L03の具体例は、右＋B＋Y＋A＋L＋RへSTARTを加えるケースです。7キー時はRが出力枠から外れ、STARTを離すとRが復帰しました。これはレポートのバイト列に対する確認で、DeltaのD05試験は未実施です。

追加で以下を確認しました。

- 全65536通りの `uint16_t` 入力で、上位4ビットを変えても出力が変わらない。
- 単キー・3キー・12キーの入力をそれぞれ3000回与えてもレポートが変わらない。
- 全4096通りで、途中に別の押下状態を挟んでも元の入力に対する結果が変わらない。
- 右＋Y＋BからBだけを離したとき、右とYが残る。全解放で全キー枠が0になる。
- 8バイトのサイズ、各フィールドの位置、コピー可能な構造を確認。
- `Keyboard` というグローバルオブジェクトをテスト側で定義してもコンパイルできる。実際のArduino `Keyboard.h` との統合ビルドはP2で扱う。

3000回の反復は状態の不変性を確認するための呼び出し回数です。実時間の30秒保持、USBでの保持、短押しの最小時間を測ったものではありません。
